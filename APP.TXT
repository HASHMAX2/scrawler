# BUILD A COMPLETE DUBAI REAL ESTATE INTELLIGENCE APPLICATION

You are working on an existing real-estate data/scraping project.

The scraper is successfully collecting data, but the raw CSV/JSON files are practically useless to a non-technical real-estate broker.

I now want you to build a **full-blown local-first Real Estate Intelligence application** that automatically ingests this data, normalizes it, analyzes it, visualizes it, and helps me make actual investment and sales decisions.

This is NOT supposed to be:

* a CSV viewer
* a basic admin dashboard
* a few charts
* a CRM
* a property listing website
* a toy analytics demo

It should feel like an internal **Bloomberg / Property Monitor / REIDIN-style intelligence terminal for Dubai real estate**, optimized for a broker/investor.

# 4. DATA ARCHITECTURE

Create a proper data layer.

Do NOT make React load dozens of CSV files directly.

Use:

### Local analytical database

Prefer:

**DuckDB**

because:

* application will initially run locally
* excellent CSV/Parquet analytics
* fast aggregations
* no database server required
* handles large datasets efficiently

SQLite can be used for application metadata if required, but analytical data should preferably use DuckDB.

Design the architecture so PostgreSQL can later replace DuckDB if the application becomes hosted/multi-user.
